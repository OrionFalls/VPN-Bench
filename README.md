# VPN-Bench

Self-hosted automated VPN server benchmarking and long-term monitoring.

## Current milestone

The project now has the foundation for the real application:

- authenticated web panel with first-run administrator setup;
- encrypted-at-rest subscription URLs;
- provider and normalized server storage;
- test campaign model with live progress state;
- two scheduling modes: equal-time and sequential;
- reusable server-filter model for regular expressions;
- SQLite storage for runs, measurements and logs;
- Docker deployment with a healthcheck;
- one-command installation for a dedicated Debian/Ubuntu VM.

The network/protocol execution layer is intentionally isolated from the web application. The next implementation stage plugs protocol adapters and real probes into the existing test campaign runner.

## UI structure

1. **Dashboard** — overall server/provider statistics and live test progress.
2. **Providers** — subscription sources, automatic metadata, custom display names and update state.
3. **Servers** — normalized server inventory with protocol, transport and security fields.
4. **Tests** — server tree selection, regex filters, duration, scheduling mode and live stop/progress.
5. **Analytics** — graphs and side-by-side comparison.
6. **Logs** — technical events and diagnostics.
7. **Settings** — storage, network, security, version and updates.

## Test scheduling

### Equal time

The requested total campaign duration is divided by the number of selected servers. Each server receives the same time slot.

Example: 10 servers and 10 minutes gives approximately 1 minute per server.

### Sequential

A server is tested until its configured probe set completes, then the next server starts immediately. The campaign continues until its overall duration expires.

The runner exposes progress, elapsed time, estimated remaining time, current server and completed/failed counts so the UI can update in real time.

## Security

The web panel is private by default and requires an administrator account created on first launch.

Subscription URLs are never returned by the normal provider list API. They are encrypted at rest with the VPN_BENCH_SECRET generated by the installer.

For internet-facing deployment, put VPN-Bench behind HTTPS and restrict access with the surrounding reverse proxy/firewall as appropriate.

## One-command installation

On a fresh dedicated Debian/Ubuntu VM:

~~~bash
curl -fsSL https://raw.githubusercontent.com/OrionFalls/VPN-Bench/main/install.sh | sudo bash
~~~

The installer:

1. installs Docker if necessary;
2. clones or updates the repository;
3. creates the local configuration;
4. generates an application encryption secret once;
5. builds and starts the container;
6. waits for the health endpoint;
7. prints the exact web-panel URL.

The first browser visit creates the administrator password.

~~~
Provider subscription
        |
        v
Subscription importer
        |
        v
Normalized server model
        |
        v
Isolated VPN adapter
        |
        v
Benchmark engine
        |
        +--> DNS
        +--> TCP/TLS/HTTP
        +--> latency / loss
        +--> jitter
        +--> download / upload
        +--> whitelist checks
        +--> stability
        |
        v
SQLite / PostgreSQL
        |
        v
Web UI / API
~~~

The production VPN connection layer will run in an isolated environment and must never modify the default route of the benchmark host itself. This keeps the benchmark VM independent from the user's main OpenWrt/router.
