# VPN-Bench — visual reference

> **Источник истины для UI:** макет «Макет дашборда VPN Bench: аналитика и тестирование», переданный в проект 2026-09-29.
>
> Этот документ фиксирует именно утверждённую визуальную концепцию. При расхождении текущей реализации с этим описанием ориентируемся на макет, а не на промежуточную реализацию.

## Общий стиль

- Тёмный левый sidebar.
- Светлая рабочая область.
- Современный SaaS / monitoring UI.
- Компактные, но не перегруженные карточки.
- Скруглённые панели, мягкие границы, лёгкие тени.
- Синие акцентные элементы и CTA.
- Статусы передаются небольшими цветными индикаторами/бейджами.
- Интерфейс должен быть информационно плотным, но визуально спокойным.
- Desktop-макет — основной визуальный ориентир.
- На мобильных устройствах **не сжимать desktop-макет**: блоки должны перестраиваться в читаемую вертикальную структуру.

## Навигация

Порядок разделов в sidebar:

1. Дашборд
2. Серверы
3. Провайдеры
4. Тесты
5. Графики
6. Сравнение
7. Логи
8. Настройки

Sidebar визуально постоянный на desktop.

## 1. Дашборд / обзор

Заголовок: **Обзор**.

Верхний ряд — четыре KPI-карточки:

- Провайдеров
- Серверов
- Тестируются сейчас
- Оптимальных / рабочих

Основная область:

- график **«Средняя скорость по времени»**;
- круговая диаграмма **«Доступность серверов»**;
- таблица **«Топ серверы (по рейтинтингу)»**.

В таблице отображаются как минимум:

- №
- провайдер
- сервер
- страна
- задержка
- скорость
- доступность

В правом верхнем углу контента показывается время последнего обновления.

## 2. Список серверов

Заголовок: **Серверы**.

Под заголовком:

- фильтр по провайдеру;
- фильтр по стране;
- фильтр по протоколу;
- фильтр по статусу;
- поиск по названию.

Основной элемент — таблица серверов.

Колонки макета:

- выбор;
- №;
- провайдер;
- сервер;
- страна;
- протокол;
- задержка;
- скорость;
- статус.

Есть массовый выбор.

Запуск теста из верхней панели списка серверов отсутствует. Запуск выполняется в разделе «Тестирование»; на странице конкретного сервера кнопка «Запустить тест» сохраняется.

## 3. Детали сервера

Заголовок содержит:

- флаг;
- название сервера;
- провайдера;

- транспорт;
- защиту;

Справа — основная кнопка **«Запустить тест»** и меню дополнительных действий.

Внутри страницы вкладки:

- Обзор

Левая карточка — текущие показатели:

- задержка;

- скорость отдачи;

- стабильность;

Правая область:

- график скорости за период;
- график задержки и потерь пакетов.

## 4. Провайдеры

Заголовок: **Провайдеры**.

Основной элемент — таблица провайдеров.

Колонки:

- выбор;
- название;
- URL подписки;
- количество серверов;
- статус;
- действия.

Статус отображается цветным компактным бейджем.

Вверху — **«Добавить провайдера»**.

Для строки провайдера предусмотрены действия редактирования и дополнительное меню.

## 5. Добавление / редактирование провайдера

Отдельная форма.

Поля:

- Название*;
- URL подписки*;
- Тип подписки;
- Описание.

Настройки:

- автоматическое обновление;
- проверка доступности при обновлении.

Кнопки:

- Отмена;
- Сохранить.

Имя провайдера может определяться автоматически, но пользователь должен иметь возможность его изменить.

## 6. Тестирование

Заголовок: **Тестирование**.

Подзаголовок объясняет, что это управление процессом тестирования серверов.

Вверху:

- **Запустить тест**;
- общий текущий прогресс;
- количество обработанных серверов;
- процент выполнения;
- кнопка **«Остановить»** во время активного теста.

Основная область разделена на две карточки:

### Сейчас тестируется

Показываются:

- флаг;
- имя сервера;
- провайдер;
- страна;
- текущий этап;
- elapsed time.

### Тип теста / результаты

Пошаговые проверки отображаются непосредственно в процессе:

- Подключение;
- DNS;
- Задержка (ping);
- HTTP (популярные сайты);
- скорость загрузки;
- скорость отдачи;
- YouTube / Telegram / GitHub и т. п.

Для каждого этапа — понятный статус.

## Мобильная адаптация

Исходный desktop-макет нельзя просто масштабировать по ширине.

На мобильном:

- sidebar превращается в компактную мобильную навигацию;
- KPI-карточки становятся вертикальными/адаптивными;
- графики занимают доступную ширину;
- таблицы получают горизонтальный scroll либо преобразуются в карточки;
- формы становятся одноколоночными;
- элементы управления не должны налезать друг на друга;
- SVG/иллюстрации должны иметь отдельную мобильную компоновку.

### Главное правило

**Визуальная структура из утверждённого макета важнее текущего кода.**

Если новая реализация отличается от макета без согласованной причины — это считается расхождением, которое нужно исправить.


## Дополнительные зафиксированные требования 28.09.2026

- Прогресс активного теста обновляется в реальном времени либо через настраиваемый интервал.
- Название провайдера при добавлении необязательно: пустое поле означает автоматическое определение.
- Технические показатели должны иметь всплывающие подсказки.
- Помимо протокола показываются transport и security; неизвестное значение — «—».
- Продолжительность теста задаётся числом + единицей времени: минуты, часы, дни, недели, месяцы.
- Режимы перебора оформляются отдельными информативными карточками и показывают актуальную информацию после выбора времени и серверов.
- Regex-фильтры исключают совпавшие серверы и должны работать во всех местах выбора серверов; следующий фильтр добавляется кнопкой «+».
- В настройках не дублируется длительность теста; там остаются системные параметры и смена пароля.
- После установки пользователь должен получить адрес веб-панели.
- Subscription URL хранится зашифрованным и не должен постоянно отдаваться фронтенду в открытом виде.
- Основная навигация использует объединённый раздел «Графики / Сравнение».
