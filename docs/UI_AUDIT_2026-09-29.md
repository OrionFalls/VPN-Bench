# UI audit — 2026-09-29

Source: user-provided PDF audit and the linked Figma reference.

## Global
- Use the Figma Dashboard as the visual source of truth for colors, spacing, typography, radii and component proportions.
- Menu/sidebar uses the Figma proportions and dark #142033 palette.
- Use squircle/Apple-like corners where appropriate rather than generic excessive rounding.
- Add subtle micro-animations across interactive UI.
- Keep the work area spacing consistent; bottom padding of cards/background must not drift between pages.

## Dashboard
- Match the Figma KPI/card layout.
- Use Figma SVG icons for menu and Dashboard where they can be stored locally.
- Keep chart implementation custom; Figma intentionally leaves the chart to implementation.

## Providers
- Subscription type is auto-detected; do not ask the user to choose it.
- No browser alert after successful save/sync; use in-app feedback and return to the provider list.
- Import and display subscription metadata: detected name, server count, expiry, traffic usage/remaining, update interval, protocols/countries where available.
- User-defined display name is optional and must remain stable across subscription refreshes.

## Servers
- Remove selection checkboxes and row numbering from the table.
- Allow drag-and-drop column reordering and persist the order locally.
- Country filter must be populated from actual server data; country flags are important.
- Do not add a fallback 🌐 icon.
- Keep protocol/transport/security visually separated.
- Add availability column.
- Preserve the compact, structured table hierarchy from the earlier design.
- Inputs must not lose focus after the first typed character.

## Tests
- Selection count must match checked servers.
- Server selection rows should be horizontal: checkbox + flag/name + protocol/transport/security.
- Start button belongs under duration/campaign configuration.
- Screening must expose live progress, current server/pass, elapsed/progress, and an explicit stop action.
- Screening result must clearly show shortlist and provide a path to a full test.
- Reduce cognitive load: advanced screening parameters should be secondary, not the main workflow.
- Combine screening, duration and current test into one right-side campaign block.

## Comparison
- Replace the ambiguous "Графики" navigation item with "Сравнение".
- Server detail remains the place for a single server's history; Comparison is for cross-server comparison.
- Keep comparison UI capable of comparing several servers using common metrics.

## Logs
- Logs must contain actual events and support level filtering.

## Settings
- One continuous page; no redundant left-side tabs.
- Password change must verify the old password server-side.
- Update check and restart actions must be wired to working endpoints.

## Future
- Consider a composite server score based on multiple measurements (speed, latency, loss, availability, stability) without hiding the underlying metrics. The exact formula is intentionally not fixed by this audit.
